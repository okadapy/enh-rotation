# EnhRot — подсказчик для энх-шамана (WotLK 3.3.5a): дизайн

Дата: 2026-09-30. Статус: на ревью у пользователя.

## 1. Цель

WeakAura-группа для Enhancement Shaman на клиенте 3.3.5a (сервер Frostmourne Rebuffed, WeakAuras 5.22 backport), которая:

1. Показывает, что нажать сейчас и что потом, на **ленте времени** (вариант B из макетов): иконки стоят на шкале и едут к черте «сейчас».
2. Выбирает действия **не по жёсткому списку, а по выгодности в текущей ситуации**: мини-симулятор проигрывает варианты на ~6 с вперёд и берёт лучший.
3. Работает **на любом уровне**: учитывает только выученные заклинания и их ранги, реальные характеристики персонажа.
4. Показывает на той же ленте **удары оружием** и окно, в котором каст Lightning Bolt не сбивает и не задерживает удар.
5. **Не прыгает**: подсказка меняется только при реальном событии боя.

Критерий успеха: в типовых ситуациях 80 уровня первое действие совпадает с ротацией wowsims (или расхождение обосновано и записано); на уровнях прокачки не предлагается невыученное и выбор совпадает с гайдами; при отсутствии событий подсказка не меняется.

### Не входит (сейчас)

- PvP-режим. В коде оставлено место (режим `pvp` в списке режимов, веса-заглушка), логики нет.
- Лечение, элементал-спек, управление тотемами поддержки (Windfury/Strength of Earth и т.п.) — только огненный тотем и Call of the Elements, потому что они влияют на урон.
- Подсветка кнопок на панелях.

## 2. Ограничения среды

- Lua 5.1, песочница WeakAuras: в `src/` нельзя `pcall`, `loadstring`, `setfenv`, `getfenv`, `_G`.
- API 3.3.5a:
  - `UNIT_SPELLCAST_*` передают имя и ранг, а не ID;
  - `GetSpellInfo` отдаёт castTime седьмым значением;
  - `COMBAT_LOG_EVENT_UNFILTERED` для `SWING_DAMAGE` не говорит, какой рукой нанесён удар;
  - нет `AuraUtil`, `C_Spell` и `RegisterUnitEvent`;
  - `C_Timer` эмулирован бэкпортом WeakAuras.
- Иконки — только пути `Interface\Icons\...` (числовые fileID клиент 3.3.5 не понимает).
- Тексты в игре — на английском (как в `frost-rotation`).
- Бюджет на один пересчёт — ≤ 2 мс, при превышении отдаём лучший найденный план.

## 3. Архитектура

Одна WeakAura-группа `EnhRot`. Весь код — модули в `src/`, склеиваются сборщиком в init-код одной ауры-хоста (подход и инструменты из `frost-rotation`: `tools/build.lua`, `tools/encode.lua`, `tools/aura.lua`).

| Модуль | Назначение | Зависит от |
|---|---|---|
| `spells` | Каталог заклинаний шамана: ID рангов, уровень, стоимость, кулдаун, общий кулдаун шоков, коэффициенты, таблицы урона по рангам | — |
| `talents` | Чтение талантов (`GetTalentInfo`) в плоскую таблицу модификаторов | `spells` |
| `snapshot` | «Глаза»: собирает снимок ситуации (см. §4) | `spells`, `talents`, `swing`, `enemies`, `ttd` |
| `swing` | «Часы ударов» (см. §6) | — |
| `enemies` | Оценка числа врагов рядом по боевому логу | — |
| `ttd` | Оценка времени жизни цели по скорости падения здоровья | — |
| `damage` | Формулы ожидаемого урона каждого действия и автоатак для заданного состояния | `spells`, `talents` |
| `model` | Переход состояния: применить действие / подождать, сдвинуть время, обновить кулдауны, баффы, дебаффы, стаки, удары | `spells`, `damage` |
| `value` | Оценка цепочки: урон на горизонте + остаточная ценность + штрафы по режиму | `damage` |
| `search` | Лучевой поиск по цепочкам действий с лимитом времени | `model`, `value` |
| `planner` | Стабилизация: удержание плана, гистерезис, учёт «летящих» заклинаний | `search` |
| `timeline` | Отрисовка ленты: иконки, черта «сейчас», отметки ударов, окно каста, точки Maelstrom, предупреждения | — |
| `recorder` | Запись снимков из реального боя в `aura_env.saved` для превращения в тесты | `snapshot` |
| `runtime` | Склейка: события игры → снимок → планировщик → лента | все |

Каждый модуль, кроме `runtime`, `timeline` и `snapshot`, — чистая логика без вызовов API игры и полностью покрывается тестами без клиента.

## 4. Снимок ситуации (`snapshot`)

Плоская таблица, которую `model` умеет копировать и сдвигать:

- `now`, `gcdRemains`, `castRemains`, `latency` (из `GetNetStats` + запас 0,1 с);
- `player`:
  - уровень, мана, макс. мана, процент здоровья;
  - сила атаки, сила заклинаний (природа, огонь);
  - шансы крита (ближний бой и заклинания), шанс попадания, хаст;
  - в движении или нет;
- `weapons`: для каждой руки — скорость, мин/макс урон (`UnitDamage`), чары (Windfury / Flametongue / Rockbiter / нет — по `GetWeaponEnchantInfo` и тексту подсказки оружия);
- `spells[key]`: выучено ли (`IsSpellKnown` по ID рангов, высший известный ранг), остаток кулдауна, стоимость, время каста;
- `buffs`: стаки и остаток Maelstrom Weapon, Lightning Shield (заряды), Flurry, Shamanistic Rage, Bloodlust/Heroism, Elemental Mastery (если есть), проки тринкетов не моделируются в первой версии;
- `target`:
  - есть ли цель, враг ли, уровень, процент и абсолютное здоровье;
  - оценка времени жизни (`ttd`);
  - дебаффы: Flame Shock — остаток, Stormstrike — заряды и остаток;
  - дистанция: ближний бой / до 20 / до 30 ярдов;
- `totems`: огненный слот (что стоит, сколько осталось, Fire Elemental ли), водяной слот (остаток — для Call of the Elements);
- `swing`: время до следующего удара правой и левой рукой, скорости, флаг «идёт автоатака»;
- `enemies`: `melee` (кто бил в ближнем бою за 2,5 с), `nearby` (кто в бою с тобой за 6 с);
- `mode`: `solo` / `group` / `raid` (авто по `GetNumRaidMembers` / `GetNumPartyMembers`), `pvp` — зарезервирован.

## 5. «Мозг»: модель, оценка, поиск

### 5.1 Действия

Все выученные заклинания из каталога, которые станут доступны в пределах горизонта:

| Группа | Заклинания |
|---|---|
| Удар оружием | Stormstrike, Lava Lash |
| Шоки | Earth Shock, Flame Shock, Frost Shock (только если выгоден, например нет Earth Shock) |
| Касты | Lightning Bolt, Chain Lightning |
| Огненные тотемы | Searing Totem, Magma Totem, Fire Nova, Fire Elemental Totem, Call of the Elements |
| Остальное | Lightning Shield, Shamanistic Rage, Feral Spirit |

Плюс два служебных действия:
- `waitSwing` — дождаться ближайшего удара (нужно для вплетения Bolt);
- `waitReady(key)` — дождаться отката конкретной кнопки.

Bloodlust/Heroism не предлагается автоматически (групповое решение), показывается как предупреждение «доступен» в группе.

### 5.2 Модель перехода (`model`)

Действие сдвигает время на `max(GCD, время каста)` (GCD 1,5 с с учётом хаста, минимум 1 с; тотемы — 1 с) и:

- уменьшает кулдауны; ставит кулдаун нажатому (у шоков — общий);
- списывает ману; Shamanistic Rage — возврат маны по формуле;
- меняет баффы и дебаффы:
  - Flame Shock ставит дебафф;
  - Stormstrike даёт заряды усиления природного урона;
  - 5-стаковый Bolt или Chain Lightning тратит стаки Maelstrom;
  - Lightning Shield ставит заряды;
- проигрывает автоатаки внутри сдвига по часам ударов (§6), в том числе:
  - задержку удара кастом;
  - сброс таймера кастом Bolt без стаков;
  - ожидаемый прирост стаков Maelstrom за удар (среднее по PPM таланта);
- уменьшает здоровье и время жизни цели на ожидаемый урон.

Случайность не разыгрывается: берётся **ожидаемое значение**. Реальный прок приходит событием и вызывает пересчёт.

### 5.3 Урон (`damage`)

Для каждого действия — ожидаемый урон по формулам 3.3.5a:
- база ранга + коэффициент × сила заклинаний или сила атаки;
- множители от талантов, дебаффов и баффов;
- крит, попадание;
- броня цели для физического урона (по уровню цели, типовая броня);
- для DoT — только тики внутри времени жизни цели.

Таблицы базового урона по рангам генерируются из `Spell.dbc` клиента (`rebuffed.mpq` поверх `locale-*.MPQ`) инструментом `tools/spelldata.lua` и коммитятся в `src/spells_data.lua`. Исследование показало, что у шамана на этом сервере числа не изменены.

Автоатаки: `(мин + макс) / 2` оружия, штраф левой руки, шанс глансинга/промаха по уровню цели, Windfury/Flametongue как ожидаемая добавка к удару.

### 5.4 Оценка цепочки (`value`)

`ценность = урон на горизонте + остаточная ценность − штрафы`.

- **Остаточная ценность** (чтобы поиск не «сжигал всё» в первые 6 с):
  - накопленные стаки Maelstrom × ожидаемая ценность стака;
  - оставшиеся тики Flame Shock (в пределах времени жизни цели);
  - готовые к концу горизонта кнопки × их урон × коэффициент дисконта.
- **Режим `solo`:**
  - урон сверх оставшегося здоровья цели = 0;
  - мана стоит дорого: цена единицы маны растёт при низкой мане и когда Shamanistic Rage на перезарядке;
  - бонус за скорое убийство (меньше полученного урона).
- **Режимы `group`/`raid`:** мана почти бесплатна, пока прогноз «хватит маны до конца боя» положительный; далее цена растёт.
- **Много врагов:** урон Fire Nova, Magma Totem и Chain Lightning умножается на ожидаемое число целей (`enemies`, с потолком по механике заклинания).
- **Сбитые или задержанные удары** — входят в урон автоатак на горизонте автоматически, отдельного правила нет.

### 5.5 Поиск (`search`)

Лучевой поиск:
- ширина луча 7, глубина до 4 действий или 6 с;
- расширение узла — все доступные действия плюс «дождаться удара, потом каст» (только для каста со временем произнесения);
- отсев дубликатов состояний;
- разнообразие: в каждом слое, кроме лучших по оценке, остаётся лучшая цепочка каждой первой кнопки (если она не хуже лучшей больше чем на 5%);
- после луча паузы ≥ 1 с в лучших цепочках первых кнопок (в пределах 2% от лучшей) пробуются заполнить готовой кнопкой;
- поиск останавливается только по числу проверенных вариантов (`NODE_CAP` = 220), не по времени: результат не зависит от скорости компьютера. В игре он идёт кусками по 2 мс за кадр (сопрограмма), обычно 3 кадра.

Результат — план: список `{ key, at, reason }`, где `at` — момент нажатия относительно «сейчас».

## 6. Часы ударов (`swing`)

Основа — `SwingTimerAPI`/`WeavingAPI` из установленного пака (wago.io/joURtkngg, бэкпорт под 3.3.5a), переписанные в чистый модуль с тестами.

**Исправления:**
1. **Определение руки.** Удар приписывается руке, чей ожидаемый момент ближе всего к факту, в допуске ±0,25 с. Вне допуска — пересинхронизация обеих рук.
2. **`SPELL_EXTRA_ATTACKS`** (Windfury): дополнительные удары не сдвигают отсчёт.
3. **Смена скорости** (`UNIT_ATTACK_SPEED`: Flurry, Bloodlust): остаток до удара масштабируется пропорционально.
4. **Касты (по коду TrinityCore/AzerothCore 3.3.5):**
   - Bolt или Chain Lightning с 0 стаков Maelstrom — сброс таймера обеих рук в конце каста;
   - с 1–4 стаками — удар не происходит во время каста и вылетает сразу после, если «созрел»;
   - с 5 стаками — мгновенный, без влияния.
5. **Мгновенные заклинания.** Сбрасывают ли таймер шоки, Stormstrike, Lava Lash и тотемы на этом сервере, неизвестно. Поэтому часы **калибруются сами**: после мгновенного заклинания сравнивают, по какому отсчёту пришёл следующий удар (старому или сброшенному). Вывод сохраняется по каждому заклинанию в `aura_env.saved` после 3 согласных наблюдений. До калибровки считается «не сбрасывает».
6. Убрана ошибочная формула `offset` из `WeavingAPI`.

**Окно каста** = интервал, в котором `время каста (со стаками и хастом) + latency < время до ближайшего удара любой рукой`. Считается для отрисовки. В поиске вплетение не отдельное правило: каст Bolt при неполных стаках — обычное действие, чья цена включает потери автоатак из `model`.

## 7. Стабильность (`planner`)

- **Точка отсчёта.** Расчёт идёт на момент `max(gcdRemains, castRemains)`. Кнопки, которые откатятся к нему, считаются готовыми.
- **Когда пересчитывать.** По событиям: `UNIT_SPELLCAST_SUCCEEDED/START/STOP/FAILED`, `UNIT_AURA` (player, target), `COMBAT_LOG` (свои удары, проки, смерть цели), `PLAYER_TARGET_CHANGED`, `UNIT_POWER`, изменения тотемов. Плюс пульс раз в 0,25 с для сдвига ленты (без нового поиска).
- **Удержание плана.** Новый план заменяет текущий, только если:
  - (а) первое действие текущего стало невозможным;
  - (б) игрок нажал не то, что было первым;
  - (в) новый план ценнее хотя бы на 8% урона, который текущий план наносит внутри горизонта (`HYSTERESIS = 0.08`); если первая кнопка текущего плана нужна в ближайшие 0,3 с (`HOLD`), порог вдвое выше (`HOLD_FACTOR = 2`).

  Иначе текущий план сдвигается по времени. Пульс без событий новый поиск не запускает — только проверяет, что текущий план ещё выполним. Показанный план меняется только когда поиск закончен. Конец отслеживаемого каста (SUCCEEDED после START) — не новое нажатие.
- **«Летящие» заклинания.** После `UNIT_SPELLCAST_SENT/SUCCEEDED` эффект заклинания (дебафф, стаки) считается уже наложенным, пока не придёт подтверждение или не пройдёт 1 с.
- **Лента** двигает иконки плавно (интерполяция позиции в `OnUpdate`). При замене плана иконки перетекают, а не перескакивают.

## 8. Лента (`timeline`)

По макету B:
- Горизонтальная шкала на 0–6 с.
- Жёлтая черта «сейчас» у левого края.
- Первое действие — крупная иконка (64 px) с подсветкой; дальше 3 иконки поменьше, каждая в своей точке времени.
- Внизу шкалы:
  - черточки ударов (правая рука — золотые, левая — серые, короче);
  - зелёное окно «начни каст здесь»;
  - светлая полоса текущей общей перезарядки.
- Справа сверху — 5 точек Maelstrom.
- Слева от черты «сейчас» — иконка-предупреждение:
  - нет Lightning Shield;
  - нет чар на оружии;
  - мало маны → Shamanistic Rage;
  - цель вне досягаемости;
  - в группе — «Bloodlust доступен» (по желанию, выключается в настройках).
- Под крупной иконкой — короткая причина (англ.): «Stormstrike · +20% to shocks».

Техника: одна WeakAura-хост (регион texture/icon, служит якорем и точкой перетаскивания). Лента рисуется собственными дочерними фреймами из кода ауры. Настройки через Custom Options:
- масштаб;
- длина шкалы;
- число иконок;
- режим (auto/solo/group/raid);
- показ причины;
- запись снимков.

## 9. Ошибки и деградация

- Неизвестные данные (уровень цели −1, нет здоровья, нет оружия) → безопасные значения по умолчанию, отмеченные в снимке флагом `guessed`.
- Любая ошибка в пересчёте → одно сообщение в чат за сессию (с текстом ошибки), лента показывает последний валидный план.
  - Как ловить без `pcall` — проверка входов и защитные ветки; `runtime` проверяет результат на валидность перед отрисовкой.
- Лимит времени поиска превышен → лучший найденный план, счётчик превышений виден в `/enhrot debug`.
- Нет цели или вне боя → лента показывает предбоевые действия: щит, чары, тотемы по желанию, либо скрыта.

## 10. Тестирование

Инструменты — как в `frost-rotation`: Docker-образ с Lua 5.1 и busted, мок API WoW в `spec/support/`.

1. **Модульные тесты** на `damage`, `model`, `value`, `search`, `planner`, `swing`, `enemies`, `ttd`, `talents`, `spells`.
2. **Сверка с wowsims** (`spec/wowsims_spec.lua`):
   - набор из ~20 типовых ситуаций 80 уровня: FT/WF-сборки, 5 стаков, Flame Shock спал, шоки на кулдауне, мало маны, AoE 3+, Fire Elemental активен и т.д.;
   - ожидаемое первое действие взято из APL wowsims (Default WF / Default FT / Phase 3);
   - расхождения допускаются только с записанным обоснованием в тесте.
3. **Прокачка** (`spec/leveling_spec.lua`): снимки уровней 10, 25, 35, 42, 50, 58 с соответствующими заклинаниями, талантами и оружием. Проверяется, что:
   - не предлагается невыученное;
   - первое действие совпадает с гайдовым приоритетом для уровня.
4. **Анти-мерцание** (`spec/stability_spec.lua`): покадровое проигрывание боя (шаг 0,05 с) без событий — первое действие не меняется; с событиями — меняется не чаще, чем события того требуют.
5. **Производительность**: поиск на типовом снимке укладывается в бюджет (замер в тесте на эталонной машине с запасом ×3).
6. **Сборка** (`spec/build_spec.lua`): строка импорта собирается, декодируется обратно, содержит все модули, в `src/` нет запрещённых функций.
7. **Реальные бои**: `recorder` сохраняет до 30 снимков с выбранным планом. Пользователь присылает `WeakAuras.lua`, `tools/build.lua import-snapshots` превращает их в фикстуры для регресс-тестов.

## 11. Риски и открытые вопросы

- **Абсолютное здоровье мобов** в 3.3.5a. Если клиент отдаёт только проценты, время жизни и «урон сверх здоровья» оцениваются по уровню цели; проверяется в игре на первом прогоне.
- **Сброс таймера мгновенными заклинаниями** — решается калибровкой (§6.5).
- **Точность числа врагов** по боевому логу — грубая. Ошибка ведёт к неправильному выбору только между AoE и одиночными действиями, заметна и правится весами.
- **Производительность в 25-ках** (у Dora были жалобы). Меры:
  - `COMBAT_LOG` фильтруется по своему GUID сразу;
  - поиск идёт не чаще событий плюс пульс 0,25 с.
